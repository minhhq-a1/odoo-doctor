# Core index

Odoo Doctor ships an index of Odoo community core, one file per version
(`src/odoo_doctor/graph/core_index/data/<version>.json.gz`, versions 17.0, 18.0, 19.0). It lists,
for every core module, the files under `static/src` and `static/tests` and the XML ids its data
files declare. It holds identifiers only (paths and ids), never source code.

## What uses it

| Rule | Looks for |
| --- | --- |
| `removed-core-js-import` | `import ... from "@module/path"` of a core JS file that an older release had and the target release lacks |
| `removed-core-xml-id` | `ref=`, `inherit_id`, `env.ref("m.id")` to a core XML id that an older release declared and the target does not |

Both rules run for target versions 18 and 19 (`--odoo-version`, or the version the manifest
declares). For any other target there is no older index to compare with, so they stay silent.

## How a finding is decided

The rule compares two snapshots; it never says "this does not exist".

- **high**: the core module is still in the target version, the file or id is not, and an older
  version had it.
- **medium**: the whole core module is gone from the target (it may have moved to enterprise),
  the import is dynamic (`import("...")`), or `env.ref` sits inside a `try`.
- **silent**: a file or id that no packaged version has seen (enterprise, OCA, created at runtime,
  or a typo), a module the scan contains (it resolves in the scan), ids Odoo creates at runtime
  (`model_*`, `field_*`, `module_*`), `@odoo/*` imports and relative imports.

For a removed JS file the help lists files with the same name in the target release, when there
are at most three.

## Rebuilding

The data is generated by hand on a machine with Odoo checkouts and committed:

```bash
python -m odoo_doctor.graph.core_index.build --odoo-path /path/to/odoo-19.0 --version 19.0
```

The output is byte-identical for the same checkout. The packaged size is capped at 3 MB by
`tests/test_core_index_size.py`. `--skip-ids-of 'l10n_*'` leaves out the XML ids of the listed
modules (their names stay, so the rules remain silent for them).

`odoo_source_path` is not an input: one source tree is one version, and the rules need two.

## Limits

- The JS reader is not a parser. Static `import` and `export ... from` count only at the start of a
  line (how Odoo formats its modules); a regex literal holding a quote can confuse the string scan
  for the rest of its line.
- Named exports are not checked: a file that still exists but no longer exports a name is not
  reported.
- Enterprise modules are not indexed.
